# SavePlus（TeleBox 插件）

`saveplus.ts` 是一个独立的 TeleBox 插件：保留 save 插件的手动保存能力，并搬入 shift 的监视、过滤、整个历史备份、静音、隐藏发送者、统计与规则导入导出，同时提供“下载到本地 → 携带来源视频封面上传 → 确认成功后删除”的本地中转。它与原 `save`、`shift` 共存，不注册、不覆盖它们的命令，也不读写它们的配置。

## 安装

- 环境：TeleBox（研究与测试基线：`TeleBoxOrg/TeleBox@c46437405be4`，锁定 `teleproto 1.229.0`、`lowdb 7.0.1`），Node.js 24。
- 安装：把仓库根目录的 **`saveplus.ts`** 放入 TeleBox 工作目录的 `plugins/` 下（或用 TPM 从该文件的直链安装），然后重载插件。只需这一个文件，它只引用宿主已有的 `@utils/*`、`teleproto`、`lowdb` 与 Node 内置模块。
- 主命令：`saveplus`，前缀跟随宿主设置（默认 `.`）。发送 `.saveplus` 查看帮助。

## 用法速览

| 场景 | 命令 |
|---|---|
| 回复保存 | 回复消息发送 `.saveplus`，可加临时目标：`.saveplus @group` |
| 链接／批量 | `.saveplus 链接1 链接2 … [临时目标]`，加 `--hide` 原生转发时隐藏“转发自” |
| 闭区间 | `.saveplus 起始链接\|结束链接 [临时目标]` |
| 默认目标 | `.saveplus to 目标`、`.saveplus target` |
| 来源说明 | `.saveplus source on\|off`、`.saveplus source` |
| 新建监视 | `.saveplus rule add 来源 目标 [选项…]`（选项：类型名、`silent`、`forward`、`hide`、`edited`、`ad`；也接受 shift 的 `hide_author`、`handle_edited`） |
| 管理监视 | `rule list`、`rule show ID`、`rule target ID 目标`、`rule pause\|resume ID[,ID]`、`rule del ID` |
| 规则选项 | `rule mode ID relay\|forward`、`rule hide ID on\|off`、`rule silent ID on\|off`、`rule edited ID on\|off`、`rule ad ID on\|off` |
| 过滤 | `rule type ID all\|photo video …`、`rule bl ID add\|del 关键词…`、`rule bl ID clear`、`rule wl ID add 正则`、`rule wl ID del 序号`、`rule wl ID on\|off` |
| 手动补漏 | `.saveplus fill 规则ID 起始\|结束 [expand] [force]`（起止可为链接或消息 ID，也可写 `100-200`） |
| 整个历史备份 | `.saveplus backup 来源 目标 [desc] [forward] [hide] [nofilter] [force]`、`backup list`、`backup status ID`、`backup pause\|resume\|cancel ID` |
| 统计 | `.saveplus stats`、`.saveplus stats 规则ID`、`.saveplus stats backup 备份ID` |
| 导出／导入 | `.saveplus export`；`.saveplus import` 换行粘贴；`.saveplus import shift [forward]` |
| 任务 | `.saveplus status`、`task`、`task list all\|attention\|uncertain`、`task show ID`、`task retry ID\|all [force] [nocover]`、`task check ID`、`task resend ID`、`task cancel ID[,ID…]\|all\|rule 规则ID\|backup 备份ID` |

目标写法：`me`（收藏夹）、`local`（本地归档，仅普通手动保存）、`here`（当前会话）、`@用户名`、`t.me/用户名`、会话 ID（如 `-100123…`），可附加 `|话题ID` 投递到论坛话题。

## 行为说明

### 普通手动保存（兼容 save）

- 优先原生转发；来源受保护（禁止转发）时自动改为复制文字、下载后重新上传媒体，临时文件随即删除。重新上传视频时尽量保留来源封面；无法获取时仍会发送，并在结果中给出警告。
- 链接或回复指向相册中的任一条时，整组一起保存；闭区间保存只处理区间内的消息，区间内的相册保持成组。
- 本地归档目录：`assets/saveplus/archive/<来源ID>/[group_<相册ID>/]msg_<消息ID>_<文件名>`，每个文件旁有同名 `.json` 来源元数据，每批生成 `index_<时间>.json`。纯文字消息跳过。归档文件是永久数据，不受中转清理影响。
- 普通手动保存不套用监视过滤，也不受监视的成功去重限制。
- 发送节奏沿用 save：每条至少间隔 0.5 秒（每分钟最多 120 条），不受监视、补漏与备份的 3 秒间隔约束。限流针对整个账号：手动保存遇到的限流会让后台任务一起冷却；等待超过 120 秒时，本次保存会停止并列出未执行的项目，而不是让命令长时间挂起；冷却期间再次手动保存会直接提示剩余时间。
- 相对原 save 的修正：闭区间与回复保存的临时目标可用；私有频道来源链接不再带负号；配置独立存放于 `assets/saveplus/`。

### 在线监视

- 只处理宿主投递的**新消息**事件（包括客户端断线重连后主动补发的新消息）；来源后续的编辑与删除不会触发保存或同步。
- **不会**在启动或重连时主动扫描离线历史。离线期间的缺口用 `fill` 手动补漏。
- 每个来源一条规则。**暂停**只停止接收新消息，已排队的任务继续执行；**删除**规则同样不删除未完成任务，它们按接收时的快照执行，可在 `task` 中查看或取消。
- 每个任务固定**接收时**的目标与过滤配置；之后修改规则只影响新消息。
- 插件自己发到目标的消息、命令消息不会被当作来源新消息再次中转。

### 投递方式与规则选项

- **本地中转**（默认）：下载后重新上传，保留来源视频封面，目标中不显示“转发自”。
- **原生转发**（`rule mode ID forward`）：不下载、速度快；可用 `hide` 隐藏“转发自”。来源开启内容保护时，该任务自动改为本地中转，并在任务中注明。
- **静音**（`silent`）：发送时不通知目标成员。
- **编辑后再存一份**（`edited`，默认关闭）：来源编辑后按新内容再保存一份（仍套用过滤），目标中已有的旧版不会被修改；同一编辑版本只保存一次，没有编辑时间的事件（如表情回应变化）不会触发。

### 过滤

- 通过条件：**类型符合 ＋ 未命中广告特征（开启时）＋ 未命中黑名单 ＋（白名单关闭，或至少命中一条白名单正则）**。白名单不能绕过广告过滤与黑名单。
- **广告过滤**（`rule ad ID on`，默认关闭）：带内联按钮、带隐藏链接（文字上的超链接）或自定义表情达到 5 个的消息不保存，最近的跳过原因显示为“疑似广告：…”。可见的普通链接不在判断范围内。该设置属于过滤配置，手动补漏、沿用规则过滤的备份与规则导出导入都会带上。
- 黑名单为大小写不敏感的关键词包含匹配；白名单为大小写不敏感正则，多条之间为“或”。白名单启用时，没有文字的消息不通过。
- 正则在配置时校验（语法、长度、明显的嵌套量词），运行时匹配有超时保护；`rule wl ID add` 保留表达式原文，可以包含空格。
- 相册按整组判断：合并全部成员的文案做文字判断，且**所有成员**类型都符合才保存整组，否则整组跳过。最近的跳过原因可在 `status` 中看到。

### 本地中转与视频封面

- 监视与补漏的所有媒体都先下载到 `temp/saveplus/staging/task_<ID>/`，上传到目标后，**先把成功记录写入磁盘，再删除该任务的中转文件**。上传失败、结果不确定、封面不能保留时，文件保留以便重试。清理只会删除中转根目录下属于该任务的目录。
- 视频封面：有发布者设置的**自定义封面**时，下载该封面的最大静态尺寸并作为视频封面上传；没有时使用来源视频的**静态缩略图**。不会用视频首帧或随机截图代替。
- 来源视频只有模糊预览或没有可用封面时，任务停在“待处理”，不会悄悄改用别的封面发送。确认可以接受无来源封面时，用 `task retry ID nocover` 显式放行。
- 相册中每个视频绑定自己的封面，保持原分组、顺序与各成员文案。
- “封面一致”指使用来源的同一张封面图并对应到正确的视频；Telegram 可能重新压缩图片，因此不保证文件字节或像素完全一致。若目标响应中没有体现封面，任务会记录警告，供在客户端核对。

### 成功去重、补漏与强制重存

- 同一账号、同一来源消息、同一目标（含话题）成功保存后，监视与补漏默认跳过；失败或尚在处理的任务不算成功。监视与补漏同时命中同一消息时，只会有一个任务执行。
- `fill` 沿用规则的过滤与目标。区间边缘的相册若有成员落在区间外，默认不纳入并提示；加 `expand` 才整组纳入。
- `force` 只绕过成功记录，仍遵守过滤、权限与封面要求。相册部分成员已保存时，任务进入待处理，需 `task retry ID force` 显式整组重存。

### 整个历史备份

- `backup 来源 目标` 不需要监视规则，按页读取来源全部历史并逐个保存单位入队；默认正序（旧→新，保持原始顺序），`desc` 为倒序。默认本地中转，`forward` 改为原生转发（可加 `hide`）。
- 来源已有监视规则时默认沿用其过滤，`nofilter` 不过滤；已成功保存到同一目标的消息自动跳过，`force` 强制重存。
- 读取历史有独立限速；遇到长时间限流（例如数十分钟）会按服务端要求等待后继续，不会跳过或把剩余消息记为失败。
- 游标与每个任务都持久保存：重启 TeleBox 后从断点继续；同一来源与目标的备份不能重复创建（避免重复转发）。系统消息自动跳过；跨页的相册整组处理。
- 单个备份同时排队的任务数受限，不会一次把全部历史塞进队列。`backup pause` 停止读取新消息（已排队的继续执行），`backup cancel` 取消并删除未开始任务的中转文件。

### 统计与规则导入导出

- `stats` 按规则与备份显示今日、近 7 天与保留期内（默认 30 天）的保存单位数与消息数；`stats 规则ID` 显示每日明细。
- `export` 导出全部规则（较多时写入 `assets/saveplus/exports/`）；`import` 后换行粘贴即可导入，同一来源的规则会被更新。
- `import shift` 直接读取现有 shift 的 `assets/shift/shift_v2.json`（也可粘贴 shift 的导出内容）：类型、`silent`、`handle_edited`、`hide_author`、话题、黑名单、白名单、暂停状态逐项转换；不合规的正则会说明原因并跳过；已有同来源规则的不覆盖。默认改用本地中转，加 `forward` 则保持 shift 的原生转发。注意：shift 启用白名单时会忽略黑名单，saveplus 中两者同时生效。

### 任务状态与操作

| 状态 | 含义 | 可用操作 |
|---|---|---|
| 排队中／处理中／发送中 | 正常执行 | — |
| 等待重试 | 限流冷却或网络等瞬时错误，按退避自动重试 | `task retry ID` 立即重试 |
| 待处理 | 权限、封面、来源消息缺失、相册不完整、磁盘不足，或自动重试次数用尽 | 处理原因后 `task retry ID [force] [nocover]`，或 `task cancel ID` |
| 结果不确定 | 发送请求可能已经执行，但无法确认（如发送中断、重启时正在发送） | `task check ID` 在目标中核对；确认未发送后 `task resend ID` |
| 已成功·待清理 | 已发送并记录成功，中转文件尚未删除 | 自动重试清理；`task retry ID` |
| 已完成／已跳过／已取消 | 结束 | — |

**取消任务**（`task cancel`）：排队中、等待重试、待处理、结果不确定的任务立即取消并删除中转文件；处理中的任务会中断下载，删除下载到一半的文件后取消；正在发送的任务因请求无法撤回，会等本次发送结束——已发出则保留为已完成，失败则不再重试，无法确认时保持“结果不确定”。批量取消可用 `task cancel all`、`task cancel rule 规则ID`、`task cancel backup 备份ID` 或 `task cancel 3,5,8`；`backup cancel ID` 同样会停止该备份处理中的任务。插件重载或停止不等于取消，处理中的任务会在重新启动后继续。

磁盘空间不足时，插件会暂停开始新的下载，并在 `status` 中显示；释放空间后用 `task retry all` 恢复。

Telegram 限流针对整个账号：某个任务等待限流期间，排在它之后的任务也会等待，以保持发送顺序；单个任务自身的网络错误不会阻塞其他任务。

发送间隔按消息条数计算：相册会一次完整发出，之后按成员数等待（例如监视中 10 张的相册发出后等待 30 秒），每分钟上限同样按条数统计。

大文件可续传：中转下载以 1 MB 为一块写入“文件名.part”，下载中途超时或中断后，重试（包括重启 TeleBox 后）会从已下载的整块处继续，不必从头下载。`task show ID` 会显示尚未完成文件的已下载大小；任务重新处理时，之前的错误显示为“上次失败原因”。

中转目录的清理：成功的任务立即删除中转文件；失败、待处理、结果不确定的任务保留中转文件，直到重试成功或执行 `task cancel`；启动时与裁剪已结束任务后，会清扫没有任务记录或任务已结束的残留目录。

### 与 shift 已知问题的对照

shift 备份功能的已知问题在 saveplus 中的处理方式：进度消息未变化或被删除不会中断任务、也不影响统计；不会出现整批失败后反复读取同一页的死循环；按错误类型与 `seconds` 字段识别限流并重试同一条；监视、补漏与备份固定 3 秒一条（每分钟 20 条），不随成功提速；每一步持久保存、可从断点继续且可重试中途失败的条目；每个任务记录失败原因（`task show`）；不依赖 TeleBox 核心的 `safeForwardMessage`；受保护来源改为本地中转；多个任务共用同一个执行者，速度不会叠加。

## 限制

- 插件只能在 TeleBox 运行期间工作；不承诺任意故障下“绝不遗漏”或“绝不重复”。网络发送与本地写盘无法构成一个原子操作，因此有“结果不确定”状态供人工核对。
- 投票、位置、联系人、骰子等特殊消息不能下载重传：自动保存会转为待处理，普通手动保存在受保护来源上会明确失败（非受保护来源仍可原生转发）。
- 提及用户的文本实体（`MentionName`）在复制或重传时会降级为纯文字。
- 目标为频道时，账号需是可发帖的管理员；目标为群组时，账号需能发送消息与媒体。
- 自定义视频封面依赖 Telegram 服务端支持；最终显示效果需在客户端验收，见 `docs/acceptance/real-telegram.md`。

## 数据位置

- 配置、规则、任务与成功记录：`assets/saveplus/data.json`（lowdb）
- 本地归档：`assets/saveplus/archive/`
- 中转与临时文件：`temp/saveplus/staging/`、`temp/saveplus/manual/`

## 开发与测试

```bash
npm install
npm run check   # 严格类型检查 + 全部测试
```

- 测试以插件的公开命令与消息事件为入口，执行真实的保存编排、lowdb 存储与中转文件，只替换外部 Telegram 与时间；另有针对生产适配层的契约测试，用真实 `teleproto` TL 对象核对封面下载、上传参数与相册组装。
- `dev/telebox-host/` 中的 `pluginBase.ts`、`generationContext.ts`、`htmlEscape.ts` 是 TeleBox 对应版本的原文件（LGPL-2.1-only，见其中的 `NOTICE.md` 与 `LICENSE`），只用于本地测试，不随插件分发。
- `saveplus.ts` 是独立实现，未复制 save、shift 的源码；其中的来源说明文案沿用了 save 的展示格式，以保持使用习惯。插件自身的许可证尚未指定，对外发布前请确定。
