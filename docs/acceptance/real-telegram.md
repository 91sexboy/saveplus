# SavePlus 真实 Telegram 验收清单

自动化测试已经覆盖保存编排、存储、文件生命周期，以及 SDK 层的上传参数。以下项目需要在**获授权的测试账号**上，对**明确列出的测试来源与目标**执行；不要向正式频道试发。记录中不要包含账号凭据、会话串或私人内容。

## 准备

1. 记录 TeleBox 提交、`teleproto` 版本、Node 版本。
2. 准备测试来源频道 A（账号可读）、测试目标频道 B（账号是可发帖管理员）、测试群组 C（账号可发媒体），以及一个开启“限制保存内容”的测试来源 P。
3. 安装 `saveplus.ts` 并重载；执行 `.saveplus rule add A B`。

## 项目

| # | 操作 | 预期 | 结果 |
|---|---|---|---|
| 1 | 在 A 发布带**自定义封面**的视频 | B 中出现视频，客户端显示与 A 相同的封面图；`task show` 无封面警告；`temp/saveplus/staging/` 为空 | |
| 2 | 在 A 发布**无自定义封面**的视频 | B 中封面与 A 的缩略图一致 | |
| 3 | 在 A 发布含 2 个视频（各自不同封面）+ 1 张图片的相册 | B 中为同一相册，顺序与 A 一致，每个视频封面各自正确，各成员文案保持 | |
| 4 | `rule add P C` 后在 P 发布视频 | C 中正常收到，封面一致 | |
| 5 | 目标为群组 C（`rule target ID C`） | 群组中正常收到 | |
| 6 | 发布 1 GB 以上的大视频 | 下载、上传完成后中转目录被清理；期间 `status` 可见任务 | |
| 7 | 发送过程中重载插件 | 任务变为“结果不确定”或继续完成；不会出现两份；`task check` 能找到已发出的消息 | |
| 8 | 撤销账号在 B 的发帖权限后发布新消息 | 任务进入“待处理”并说明权限原因，中转文件保留；恢复权限后 `task retry` 成功 | |
| 9 | 重载插件后再发布新消息 | 只收到一份，说明只有一套监听在工作 | |
| 10 | 停止 TeleBox 一段时间，期间在 A 发布消息，再启动 | 启动后不会自动补抓；`fill` 指定范围后补齐，已保存的不重复 | |
